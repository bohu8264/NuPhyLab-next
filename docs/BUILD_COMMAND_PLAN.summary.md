# Windows 可以单独生成签名安装包

## 现在能做什么

Windows 已有独立代码签名入口。代码签名用于核对软件发布者；生成这样的安装包，无需先开启应用自动更新。

在 Windows Git Bash，也就是 Windows 上的 Bash 命令环境中，进入仓库根目录运行：

```bash
bash ./nuphylab release --sign
```

新入口参考 Talkflow 的 Windows 打包方式。先编译，再给主程序和五个配套程序签名，封包时保持已签文件不变，最后签安装器。所有签名都必须核对发布者和时间戳，完成后才提供安装包与校验清单。

## 打包机需要准备什么

使用沃通签名工具、对应驱动和 ePass2003 UKey。UKey 是保存签名私钥的硬件设备，需要在实际 Windows 桌面使用，不能通过 SSH 或后台服务完成真实签名。

工具路径、证书指纹和时间戳地址已采用 Talkflow 的公开默认配置，无需每次设置环境变量；有特殊需要仍可单独覆盖，错误配置会报错。打包机仍须装好工具、驱动和对应证书，不会自动复制证书或密码。每次运行在签名时安全输入一次 PIN，旧密码环境变量不能跳过输入；编译进程不会收到 PIN 或自动更新私钥。

## 成功和失败怎样区分

成功后，本轮独立目录的 artifacts 文件夹提供签名安装器、文件校验值和构建记录。发生签名、时间戳或封包失败时保留现场，并返回失败，不自动改成未签名成功，也不自动重试私钥操作。

打包不会启动应用、安装程序或上传 GitHub。自动更新保持关闭；原有完整更新发布命令继续保留。内部卸载器和安装插件没有新增独立签名步骤。

## 已经验证和仍待确认的部分

隔离测试已覆盖默认配置、可选覆盖、强制输入 PIN、更新关闭、密码隔离、错误发布者、缺少时间戳及签名和封包失败。撤掉独立签名逻辑后，用例确实失败，恢复后通过。Windows 实际编译和封包验证已通过，封包保持主程序字节不变，未调用签名工具；真实 UKey 签名与安装、升级仍待实际打包机验收。

本轮只提供 Windows 的上述命令。Mac 统一打包、环境检查命令和失败补签仍属于后续方案。
