# Windows 可以单独生成签名安装包

## 现在怎样使用

Windows 已有独立代码签名入口。现在同一条命令会先检查环境、自动准备项目依赖，再编译和签名，无需分别记住前端依赖安装命令。代码签名用于核对软件发布者，自动更新继续关闭。

在 Windows Git Bash，也就是 Windows 上的 Bash 命令环境中，进入仓库根目录运行：

```bash
bash ./nuphylab release --sign
```

使用 PowerShell 时，完整调用 Git Bash 的方法见详细说明，避免误入系统的 Linux 子系统入口。

## 哪些会自动准备

入口先列出缺少的系统工具和签名条件，再通过已有 rustup 准备项目指定的 Rust 编译工具，按两份锁定清单安装根目录和界面依赖。锁定清单决定具体版本，安装不会自动更新它。

首次准备会重建对应的依赖目录；以后核对完整时复用，清单变化或缺少 TypeScript 等文件时自动修复。下载、安装和编译持续显示进度，失败时显示具体原因并停止。请勿同时手动安装依赖或运行另一构建。

打包机仍须提前装好 Node/npm、rustup、C++ 工具和 Windows SDK，以及沃通驱动、UKey 和对应证书。系统软件缺失会说明准备方法。Node 支持 Windows x64 的 22 及以上版本，已验收版本为 22.23.5；入口不更换系统 Node。

## 签名与产物有什么约束

工具路径、证书指纹和时间戳地址采用 Talkflow 的公开默认值，仍可单独覆盖。每次运行在编译完成后安全输入一次 PIN，旧密码环境变量不能跳过输入；编译进程不会收到 PIN 或更新私钥。

主程序、五个配套程序和安装器逐项核对发布者与时间戳。成功目录提供安装器、校验值和构建记录；失败保留现场，不自动重试私钥操作。打包不会启动应用或安装器，也不上传 GitHub。内部卸载器和插件没有新增单独签名步骤。

## 已验证和仍待确认的部分

本次本地自动检查、真实 npm 安装与缺文件修复、超过 30 秒的等待验证已通过。此前 Windows 编译和封包验证通过；本次新增流程的 Windows PowerShell、Rust 安装和构建按用户要求暂未执行，真实 UKey 签名及安装升级也仍待验收。
