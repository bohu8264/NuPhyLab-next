# Windows 构建和上传都有独立入口

## 现在怎样使用

在 Windows Git Bash，也就是 Windows 上的 Bash 环境中，进入仓库根目录运行。三条命令各自独立，按需要逐条执行：

本地构建签名包：

```bash
bash ./nuphylab release --sign
```

上传为草稿：

```bash
bash ./nuphylab upload
```

核对草稿后，显式公开为预发布：

```bash
bash ./nuphylab upload --publish
```

第一条检查环境、自动准备依赖并生成签名包；第二条把最近一次成功构建上传成草稿；第三条在核验附件后公开为预发布。上传不需要再输入版本、目录、仓库或标签，也不需要签名 PIN。

## 参数从哪里来

新构建会记录版本、构建编号、源码提交、仓库和文件摘要。摘要是识别文件内容的校验值。上传读取这份记录，核对安装器和六个程序的签名，再把安装器、校验文件和构建清单三个附件上传到对应仓库。

打包仍按 Talkflow 的公开默认配置签名，PIN 在编译完成后安全输入一次。根目录和界面依赖会自动准备，完整时复用。系统工具、驱动、UKey 和证书需要提前装好；上传还需要已登录的 GitHub CLI。

## 哪些情况会停止

源码有未提交的实现变更、构建期间改变、签名或摘要不符、来源提交尚未推送或无权读取时，上传会说明原因并停止。本地包会保留，不自动提交或推送代码。

旧包缺少源码来源，不能从当前分支猜测它的提交号，需要重新打包一次。目录时间不会作为选择包的依据。

中断后可重跑，同一个包仍对应同一个草稿。相同附件跳过，缺失附件补齐，内容冲突停止；已公开版本不自动修改。草稿附件核对完成后，只有显式使用公开参数才发布。

## 已验证和仍待确认的部分

本地自动检查已覆盖来源、参数自动读取、上传中断、重复执行、摘要冲突和显式公开。所有 GitHub 写入均用替身验证，没有实际上传或发布；Windows 新入口及新构建记录仍待平台验收。

自动更新继续关闭，预发布不设为 Latest，不影响现有正式下载。命令不启动应用、安装器或浏览器。Mac 统一构建和失败补签仍属于后续方案。
