# Windows 已接到官方新版

## 这次完成了什么

**现有 Windows 版本已集成到官方 1.2.54 的独立分支。** 保留了官方新增的 Mac 功能；Windows 的窗口、后台、灯光恢复、输入、声音和已有 AI 入口一起迁入，没有直接用旧目录覆盖新版。

代码审查已完成，并修复了“打开官方工具”误报失败的问题。三个程序部分现在共用同一个官方地址；键盘未安全释放时仍会阻止交接。本地提交按本轮授权进行，没有推送或发布安装包。

## 新旧功能怎样放在一起

Windows 使用新版界面，可以管理已支持的功能入口，继续编辑和保存灯光作品。屏幕回放、Dock 场景等 Mac 专属能力保留在 Mac，没有假装已支持 Windows。

两端的固件资格也分开处理。Mac 默认固件升级，不会自动打开 Windows 改键、休眠写入或未知固件。已有自定义按键不接管、不重置。

## 检查结果怎样

Windows 相关检查通过 263 项，1 项按平台跳过；新版设置等相关检查通过 52 项；审查修复后，相关检查 48 项、桌面宿主 25 项通过。前端构建、Rust 自动测试、Mac 代码检查和 Windows 原生组件的静态检查通过。

共享回归仍有 24 个失败，已在未改动的官方原版逐项复现，错误内容相同。本次没有顺带修改这些上游问题，完整报告保留清单。

## 现在能发包测试吗

**本轮完成的是代码集成与自动检查，没有生成或启动新的 Windows 安装包。** 完整 Windows 桌面检查还缺本机资源编译工具，不能说已全部通过。

下一轮需要在真实 Windows 构建，集中验证保存重开、灯光播放、恢复原灯效和退出恢复，再检查输入、声音、安装与升级。旧版实机结果不代替新版体验。

## 还有哪些边界

真实改键、实体 AI 按键、审批和听写等尚未完成的能力继续关闭。真实签名、自动更新和 Windows 11 验收也分别保留。

统一 release 命令仍是另一份待审核方案，本次只迁入已有构建能力。下一步安排 Windows 构建和实机测试。
